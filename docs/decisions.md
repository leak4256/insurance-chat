## סטאק (מאושר)

| רכיב | בחירה |
|---|---|
| Framework | Next.js + TypeScript — **בפועל 16.2**, לא 15 כמו במפרט (יציב נוכחי) |
| UI | Tailwind v4 + shadcn/ui |
| AI SDK | Vercel AI SDK **v5 מוצמד** (npm נותן v7 — גולגל אחורה לפי המפרט) |
| מודל | במפרט: Claude Haiku 4.5. **בפועל: Google** — ראו §מודלים |
| Vector DB | Supabase pgvector |
| Embeddings | Voyage `voyage-3.5-lite` |
| מייל OTP | Resend |
| אירוח | **Railway** (~$5/חודש — המשתמשת עברה מ-Vercel Pro כדי לחסוך) |

**תקציב:** תקרה $50/חודש. **~350 לקוחות** (תוקן 28.07.2026 — ההערכה הקודמת של ~100 הייתה שגויה).

**עלות Surense:** תוסף בתשלום בחשבון הסוכנות, 120₪+מע"מ ≈ $37/חודש, הפעלה עצמית (קטגוריית API). המשתמשת החליטה שזה **נספר** בתקציב הצ'אט. נחוץ רק משלב 2 → שלב 1 ~$11–16/חודש, מלא ~$48–53/חודש (על הגבול מול התקרה; מיטיגציה = caching אגרסיבי).

## מדיניות תשובות — שלוש רוויזיות, קראי את כולן

### מקור (אפיון §7) — **מבוטל**
כלל הפניה לרחלי במייל (FR-7).

### רוויזיה 19.07.2026
המשתמשת **הסירה לגמרי** את ההפניה "צרו קשר עם רחלי במייל" מה-system prompt — לא אהבה שזה מופיע בכל תשובה.

סדר התשובות החדש:
1. RAG
2. ידע כללי (מותר! בלי שורת מקור)
3. fallback של אי-ודאות אמיתית

- שאלות מטא על הבוט + שאלות מחוץ לתחום/טכניות → בדיוק המשפט: **"אני מורשה לענות על שאלות בנושאי פנסיה ופיננסים"**
- ההיקף הורחב ל**ביטוח + פנסיה + פיננסים** (המשתמשת אישרה)
- משפט ההסתייגות ("המידע כללי בלבד...") **רק** על תשובות מידע כללי, לא על תשובות מעוגנות במסמכים

### רוויזיה 03.08.2026
"אין לי הרשאה לענות על זה" שימש לשני מצבים שונים (מחוץ לתחום **וגם** אי-ידיעה אמיתית) — המשתמשת רצתה הפרדה.

תוקן ב-[system-prompt.ts:21](../src/ai/system-prompt.ts):
- המשפט הזה שמור **אך ורק** לשאלות מחוץ לתחום/מטא
- כש-RAG לא מוצא **וגם** הידע הכללי לא בטוח → הבוט אומר בפשטות שאין לו מידע מדויק על זה ומציע לבדוק מול הסוכנת. אין יותר ערבוב בין "לא יודע" ל"לא מורשה"

### רוויזיה 18.08.2026 — הקשר שיחה + הפניה לסוכנת בלבד

לאה הראתה שיחה אמיתית שבה **שאלת המשך קצרה נדחתה בטעות**: אחרי שאלה על הפנסיה, ההודעה
"מתי היתה ההפקדה האחרונה?" קיבלה את משפט הסירוב "אני מורשה לענות על שאלות בנושאי פנסיה ופיננסים".

**הסיבה:** הפרומפט הורה לסווג לפי נושא, בלי שום הוראה להתחשב בהקשר השיחה — הודעה קצרה בלי מילות מפתח
סווגה כמחוץ לתחום. **זה היה באג אמיתי** (לאה אישרה; שאר שתי ההערות שהעליתי היו לדעתה ליטוש, לא באגים).

תוקן ב-`src/ai/system-prompt.ts`:
- **סיווג לפי הקשר השיחה כולה, לא לפי ההודעה הבודדת** — שאלת המשך שממשיכה נושא שנדון היא בתחום
- בספק — להניח שבתחום ולענות/לבקש הבהרה; משפט הסירוב שמור למקרים שברור שהם חיצוניים
- לענות קודם על מה שנשאל במדויק (נשאלת על הפנסיה → לפתוח בסכום הפנסיה, לא בסך הכולל)
- **כשחסר נתון — הפניה לסוכן/ת בלבד.** אסור להפנות לחברת הביטוח, לבית ההשקעות או לקרן.
  (הנוסח "מומלץ לבדוק מול חברת הביטוח" מעולם לא היה בפרומפט — המודל אילתר אותו.)

**גם:** `summarizeHoldings` ב-`src/lib/surense.ts` מעביר עכשיו גם `hafkadot`, `hafkadotHishtalmut`,
`hafkadotGemelLeashkaa` ו-`validityMonth` — שדות שהיו במילון השדות אך מעולם לא הועברו למודל.
זה מאפשר לענות "ההפקדה החודשית היא X, נכון לחודש Y". **מועד ההפקדה האחרון המדויק** קיים רק בגיליון
"מעקב הפקדות" של דוח המסלקה, וחסום על אותו חסם 500 — שתי היכולות ייפתחו יחד.

⚠️ לא אומת חי (worktree ללא certs/env — ראו `env-and-ops.md`). typecheck נקי, UI נטען. **דורש בדיקה על :3000.**

## החלטות נוספות

**אימות:** כרטיס התחברות בתוך הצ'אט → ת"ז+אימייל מאומתים מול Surense → OTP בן 6 ספרות במייל → session מסוג httpOnly. הכלי `get_customer_data` **לא מקבל פרמטר ת"ז** (מוזרק מה-session). **אין מידע אישי at rest.**

**מסירה לאדם:** אין ערוץ אנושי חי. (מבוטל חלקית ע"י רוויזיה 19.07 לעיל.)

**תוספות שהמשתמשת ביקשה:** הערכת RAG (golden set + LLM-judge), guardrails, הפשטת ספק AI (מודל מוגדר ב-env), זיכרון שיחה, מטא-דאטה על chunks (source/page/domain/version).

**UI לפני התחברות:** כפתור LOGIN עם תווית עברית מזמינה בראש כותרת הצ'אט; לחיצה פותחת את כרטיס ההתחברות. אחרי התחברות → צ'יפ "מחובר/ת" + יציאה. (FR-10)

## מה נבנה ואומת

**שלב 1 (19.07.2026) — חי ועובד end-to-end, חסר תוכן.**
Next.js 16.2, AI SDK v5, ממשק צ'אט RTL מלא, `/api/chat` (streaming, rate-limit, חלון הזזה + זיכרון סיכום), מודול `src/ai/` (provider/embedder/system-prompt/tools/retrieval), `supabase/schema.sql` (vector(1024), match_chunks), `scripts/ingest.ts` (בדיקת שפיות עברית, רענון פר-מסמך), `scripts/eval` (recall@5 + שופט Sonnet, ספים לפי המפרט).

**שלב 2 (19.07.2026) — קוד מלא.**
כרטיס התחברות בצ'אט (ת"ז+אימייל → Surense `customers/search` → OTP 6 ספרות דרך Resend → session חתום httpOnly, חידוש מתגלגל של 30 דקות דרך Set-Cookie על ה-stream); כלי `get_customer_data` (בלי פרמטר ת"ז, מוזרק מ-session, נרשם בצד שרת רק כשמאומת); כלי `request_login` בצד לקוח (בלי execute) — המודל קורא לו בשאלות אישיות וה-UI מציג את הכרטיס; מסך אדמין `/admin` (התחברות ADMIN_PASSWORD → העלאת PDF/TXT עם מטא-דאטה → Supabase Storage bucket `knowledge` + ליבת ingest משותפת `src/lib/ingest.ts` שחולצה מ-`scripts/ingest.ts` → רשימת/מחיקת מסמכים).

קבצים חדשים: `src/lib/{signing,session,otp,mailer,surense,audit,ingest,domains}.ts`, `api/auth/{start,verify,resend,session,logout}`, `api/admin/*`, `supabase/schema-phase2.sql`.

אבטחה: תגובות אחידות חסינות-מנייה; OTP מגובב, 5 ניסיונות, cooldown 60 שניות לשליחה חוזרת; לוג ביקורת = אירוע+UUID בלבד.

**✅ אומת מקצה לקצה 21.07.2026** — התחברות אמיתית דרך ממשק הצ'אט (רשומת Surense של לאה, id `3463bf43-…`, ת"ז 211953211 / leak4256@gmail.com): auth/start → Make search_customers מצא לקוח + אימות מקומי חוזר עבר → OTP (נקרא מלוג השרת) → auth/verify הגדיר session, firstName "לאה" נגזר מ-fullName → כותרת "מחובר/ת · לאה" → שאלה "אילו ביטוחים יש לי ומה הצבירה בפנסיה" → המודל קרא ל-`get_customer_data` → summarizeHoldings(tromStats) → תשובה נכונה עם **כל** הערכים תואמים ל-tromStats הגולמי (פרמיית חיים 28.28, פנסיה 67,878, השתלמות 18,347, פיצויים 27,384, סה"כ 86,225, קצבה צפויה 1,620.72, שארים 1,534,229). לוג השרת נקי.

**באג UI שתוקן 21.07.2026 (chat.tsx):** ה-LoginCard שנפתח מהכותרת עבר render **אחרי** לולאת ההודעות → הוצמד לתחתית, אז אישור "התחברתם בהצלחה" הירוק נדחף מתחת לכל הודעה חדשה לנצח (`headerCardOpen` מעולם לא אופס בהצלחה). תיקון: state בשם `headerCardAnchorId` — `openHeaderCard()` רושם את מזהה ההודעה האחרונה בזמן הפתיחה, והכרטיס עובר render בתוך הלולאה מעוגן להודעה ההיא (או בראש השרשור אם נפתח לפני הודעות); דגל נגזר `showHeaderCard` מונע כרטיסים כפולים.
